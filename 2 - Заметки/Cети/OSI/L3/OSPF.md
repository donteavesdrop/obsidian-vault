**OSPF (Open Shortest Path First)** — это протокол динамической маршрутизации, предназначенный для обмена маршрутной информацией внутри одной автономной системы (AS). Он относится к классу протоколов, отслеживающих состояние каналов (Link-State), и использует алгоритм Дейкстры для расчёта наилучшего пути к каждому пункту назначения. OSPF был разработан IETF в 1988 году и остаётся одним из самых популярных внутренних протоколов шлюза (IGP) в корпоративных и провайдерских сетях. Последняя версия протокола описана в RFC 2328.

### Особенности

**Link-State против Distance Vector.** В отличие от протоколов типа Distance Vector (например, RIP), где каждый маршрутизатор знает только о своих соседях, OSPF строит полную карту топологии сети. Каждый маршрутизатор хранит базу данных состояния каналов (LSDB), которая содержит информацию о всех маршрутизаторах и связях между ними в пределах зоны. На основе этой базы каждый маршрутизатор независимо вычисляет оптимальные маршруты с помощью алгоритма SPF (Shortest Path First), также известного как алгоритм Дейкстры.

**Иерархическая структура зон (Areas).** Для повышения масштабируемости и уменьшения нагрузки на устройства большие сети OSPF разделяются на зоны (areas). Все зоны должны быть подключены к магистральной зоне (Area 0 или backbone). Такой подход ограничивает распространение информации о состоянии каналов пределами зоны, что уменьшает размер базы данных LSDB и ускоряет сходимость сети. Зоны позволяют локализовать изменения топологии внутри зоны и упрощают управление крупными сетями.

**Типы маршрутизаторов и LSA.** В зависимости от расположения и роли в сети различают несколько типов OSPF-маршрутизаторов:

- **Внутренний маршрутизатор (Internal Router)**: все его интерфейсы находятся в одной зоне.
    
- **Пограничный маршрутизатор зоны (ABR, Area Border Router)**: соединяет магистральную зону с другими зонами.
    
- **Пограничный маршрутизатор автономной системы (ASBR, Autonomous System Boundary Router)**: обменивается маршрутами между OSPF-доменом и другими протоколами маршрутизации.
    

Информация о топологии передаётся с помощью объявлений о состоянии каналов (LSA). Разные типы LSA отвечают за разные виды информации: тип 1 (Router LSA) описывает состояние интерфейсов маршрутизатора в пределах зоны, тип 2 (Network LSA) генерируется назначенным маршрутизатором (DR) в сетях с множественным доступом, тип 3 (Summary LSA) передаёт информацию между зонами, а тип 5 (External LSA) распространяет маршруты из внешних сетей, полученные через ASBR.

**Метрика стоимости (Cost).** OSPF использует метрику, называемую стоимостью (cost), которая рассчитывается на основе пропускной способности интерфейса. Стоимость обратно пропорциональна пропускной способности: чем выше скорость интерфейса, тем ниже его стоимость. Стоимость маршрута равна сумме стоимостей всех исходящих интерфейсов на пути к месту назначения. По умолчанию эталонная полоса пропускания составляет 100 Мбит/с, поэтому для интерфейса 100 Мбит/с стоимость равна 1, а для 10 Мбит/с — 10. Администратор может вручную настраивать стоимость для реализации политик маршрутизации.

**Типы сообщений и работа поверх IP.** OSPF инкапсулируется непосредственно в IP-пакеты (с номером протокола 89), не используя TCP или UDP. Протокол определяет пять типов сообщений: Hello (для обнаружения соседей), Database Description (DD) (для синхронизации базы данных LSDB), Link-State Request (LSR), Link-State Update (LSU) и Link-State Acknowledgment (LSACK). Для обмена служебной информацией OSPF использует multicast-адреса 224.0.0.5 (AllSPFRouters) и 224.0.0.6 (AllDRouters).

**Установление соседства и синхронизация LSDB.** Процесс работы OSPF начинается с обмена Hello-пакетами. Когда два маршрутизатора обнаруживают друг друга, они устанавливают отношения смежности (adjacency) при условии совпадения параметров (таймеры Hello и Dead, область, тип аутентификации). Затем маршрутизаторы синхронизируют свои базы данных LSDB с помощью обмена DD, LSR и LSU-пакетами. После полной синхронизации маршрутизаторы считаются находящимися в состоянии Full и имеют идентичные базы данных LSDB. Они продолжают периодически отправлять Hello-пакеты (по умолчанию каждые 10 секунд) для подтверждения активности соседа. Если в течение таймера Dead (по умолчанию 40 секунд) маршрутизатор не получает Hello от соседа, он считается недоступным.

**Выбор назначенного маршрутизатора (DR/BDR).** В широковещательных сетях (например, Ethernet) для уменьшения количества соседств и объёма служебного трафика OSPF выбирает назначенный маршрутизатор (DR) и резервный назначенный маршрутизатор (BDR). Все маршрутизаторы в сегменте устанавливают полные отношения смежности только с DR и BDR, которые отвечают за распространение информации о состоянии каналов в этом сегменте. Если DR выходит из строя, BDR автоматически берёт на себя его функции.

**Быстрая сходимость.** Благодаря использованию алгоритма Дейкстры и мгновенному оповещению о изменениях топологии через LSA, OSPF обеспечивает очень быструю сходимость сети. При изменении состояния канала (например, отключении ссылки) маршрутизатор, обнаруживший изменение, немедленно генерирует новое LSA и рассылает его всем соседям. Это позволяет всем маршрутизаторам пересчитать свои таблицы маршрутизации за секунды.

**Аутентификация.** OSPF поддерживает аутентификацию для защиты от несанкционированного обмена маршрутной информацией. Доступны три типа аутентификации: нулевая (аутентификация отключена), простая (пароль передаётся в открытом виде) и криптографическая (используется MD5 или SHA для создания дайджеста сообщения). Аутентификация настраивается для всей зоны.

**Независимость от производителя.** OSPF является открытым протоколом, поддерживаемым практически всеми производителями сетевого оборудования (Cisco, Juniper, Huawei, MikroTik, HP и другими). Это позволяет строить мультивендорные сети без привязки к одному поставщику.

### Как и где применяется

1. **Корпоративные сети среднего и крупного масштаба.** OSPF является стандартным выбором для маршрутизации внутри организаций с большим количеством зданий, этажей и маршрутизаторов. Он обеспечивает быструю сходимость, оптимальную маршрутизацию и устойчивость к отказам.
    
2. **Операторские инфраструктуры.** Провайдеры связи используют OSPF для внутренней маршрутизации в своих сетях, особенно в сочетании с BGP для обмена маршрутами между автономными системами.
    
3. **Центры обработки данных (ЦОД) и облачные среды.** В дата-центрах OSPF применяется для маршрутизации между серверными фермами, коммутаторами и маршрутизаторами, обеспечивая отказоустойчивость и балансировку нагрузки (ECMP — Equal-Cost Multi-Path).
    
4. **Мультивендорные сети.** Благодаря своей открытости, OSPF идеально подходит для сетей, где используется оборудование от разных производителей, обеспечивая совместимость и стандартизацию.

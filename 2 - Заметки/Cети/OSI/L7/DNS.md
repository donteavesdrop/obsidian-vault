**DNS (Domain Name System)** — это распределённая система, преобразующая удобные для человека доменные имена (например, `example.com`) в IP-адреса, понятные компьютерам (`93.184.216.34`). По сути, это «телефонная книга» интернета, жизненно необходимая для его работы[](https://ru.wikipedia.org/?oldid=369082). Протокол работает на **прикладном уровне (Layer 7)** модели OSI и для своих запросов использует транспортный уровень (UDP или TCP)[](https://habr.com/ru/articles/906802/)[](https://ru.wikipedia.org/w/index.php?diff=22104654)[](https://stackoverflow.com/questions/21654632/at-what-layer-in-the-protocol-stack-does-dns-happen).

---

### Принцип работы

Процесс преобразования имени в IP-адрес (разрешение имени) строится на взаимодействии клиента (резолвера) и серверов DNS, организованных в строгую иерархию.

**Иерархическая структура.** Пространство доменных имён — это перевёрнутое дерево. На его вершине находится корневой домен, обозначаемый точкой (`.`). Далее следуют домены верхнего уровня (TLD), такие как `.com`, `.org` и национальные `.ru`, `.de`. Ещё ниже находятся домены второго и последующих уровней (например, `example.co.uk`), за которые отвечают конкретные организации.

**Типы DNS-запросов.** Клиент отправляет запрос и ждёт ответ. Существует два основных типа:

- **Рекурсивный запрос (Recursive).** Клиент (например, ваш браузер) поручает DNS-серверу всю работу по поиску адреса. Сервер обязан либо вернуть найденный IP-адрес, либо сообщить, что запись не найдена[](https://www.techtarget.com/searchnetworking/answer/Recursive-vs-iterative-DNS-queries-Whats-the-difference).
    
- **Итеративный запрос (Iterative).** Сервер не выполняет поиск за клиента. Если он не знает ответа, он просто возвращает ссылку (реферал) на другой DNS-сервер, который может быть ближе к цели. Клиент сам продолжает запросы к следующим серверам[](https://www.techtarget.com/searchnetworking/answer/Recursive-vs-iterative-DNS-queries-Whats-the-difference).

### Особенности

**Использование UDP и TCP порта 53.** DNS — один из немногих протоколов, активно использующих оба основных транспортных протокола[](https://ru.wikipedia.org/w/index.php?diff=22104654):

- **UDP (User Datagram Protocol):** стандарт для обычных запросов и ответов. UDP быстр, но имеет ограничение на размер ответа в 512 байт.
    
- **TCP (Transmission Control Protocol):** применяется для передачи больших ответов (например, при пересылке целых зон между серверами или использовании DNSSEC), когда данные не умещаются в лимит UDP.
    

**Кэширование информации.** Все DNS-серверы сохраняют полученные ответы в своём кэше на определённое время (TTL — Time To Live). Благодаря этому при повторном запросе к тому же домену сервер может ответить мгновенно, не обращаясь к вышестоящим иерархиям, что значительно снижает нагрузку на сеть и ускоряет работу интернета.

**Распределённость и отказоустойчивость.** Система устроена так, что информация о домене не хранится в одном месте. Каждый домен поддерживается минимум двумя (часто гораздо больше) авторитативными DNS-серверами, разнесёнными географически. Если один сервер недоступен, запросы обрабатываются другим, что делает систему чрезвычайно живучей.

**Типы ресурсных записей (Resource Records).** Вся информация в DNS хранится в виде записей разных типов. Ключевые из них[](https://ru.wikipedia.org/wiki/%D0%A2%D0%B8%D0%BF%D1%8B_%D1%80%D0%B5%D1%81%D1%83%D1%80%D1%81%D0%BD%D1%8B%D1%85_%D0%B7%D0%B0%D0%BF%D0%B8%D1%81%D0%B5%D0%B9_DNS):

- **A (Address):** связывает доменное имя с IPv4-адресом. Самая распространённая запись.
    
- **AAAA (Quad A):** аналогична записи A, но для IPv6-адресов.
    
- **CNAME (Canonical Name):** создаёт псевдоним для доменного имени, позволяя обращаться к нему по разным именам.
    
- **MX (Mail Exchange):** указывает почтовые серверы, которые принимают электронную почту для домена.
    
- **TXT (Text):** хранит произвольную текстовую информацию, часто используется для проверок прав на домен (например, в системах верификации).
    
- **NS (Name Server):** определяет, какой DNS-сервер является авторитативным для данной зоны (домена).

### Как и где применяется

**Веб-серфинг.** Без DNS вы не смогли бы открыть ни один сайт по его имени. Когда вы вводите `yandex.ru`, браузер отправляет DNS-запрос, получает IP-адрес и только после этого может установить соединение с сервером Яндекса[](https://habr.com/ru/articles/906802/).

**Электронная почта.** Почтовые серверы используют DNS для поиска адресата. Когда вы отправляете письмо на `user@example.org`, ваш почтовый сервер ищет MX-запись для домена `example.org`, чтобы узнать, какому серверу нужно передать сообщение.

**Безопасность и борьба с фишингом.** Современные системы безопасности используют DNS для блокировки вредоносных и фишинговых сайтов. Существуют публичные DNS-серверы (например, от Cloudflare 1.1.1.1 или Google 8.8.8.8), которые не только быстро отвечают на запросы, но и фильтруют опасные ресурсы. Также протокол **DNSSEC** (DNS Security Extensions) позволяет проверять подлинность DNS-ответов, защищая от подмены адресов[](https://ru.wikipedia.org/wiki/%D0%A2%D0%B8%D0%BF%D1%8B_%D1%80%D0%B5%D1%81%D1%83%D1%80%D1%81%D0%BD%D1%8B%D1%85_%D0%B7%D0%B0%D0%BF%D0%B8%D1%81%D0%B5%D0%B9_DNS).

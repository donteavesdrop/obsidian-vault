**JSON (JavaScript Object Notation)** — это текстовый формат обмена данными, основанный на синтаксисе JavaScript, но независимый от какого-либо языка программирования[](https://preprod.arquivo.pt/noFrame/patching/patching/record/20131106065644mp_/http://en.wikipedia.org/wiki/Json). В модели OSI его принято относить к уровню представления (Layer 6), поскольку он занимается «переводом» структурированных данных в формат, пригодный для передачи по сети, и обратно[](https://news.workers.tools/item?id=13934219).

---

### Принцип работы

Процесс обмена данными с помощью JSON представляет собой двухэтапную процедуру, известную как сериализация и десериализация.

**Сериализация** — это преобразование сложных объектов языка программирования (например, на Python или Java) в универсальную текстовую строку JSON. Эта строка затем отправляется по сети. На принимающей стороне выполняется **десериализация** — обратное преобразование JSON обратно в структуры данных, понятные принимающему приложению[](https://docs.oracle.com/javaee/7/tutorial/jsonp001.htm).

Формат поддерживает всего две основные структуры данных: **объект** (набор пар «ключ-значение», заключённый в фигурные скобки `{}`) и **массив** (упорядоченный список значений, заключённый в квадратные скобки `[]`).

Вложенность объектов и массивов друг в друга позволяет описывать данные практически любой сложности[](https://docs.oracle.com/javaee/7/tutorial/jsonp001.htm). Ниже приведён пример, демонстрирующий все ключевые синтаксические конструкции:

json

{
  "firstName": "Duke",
  "lastName": "Java",
  "age": 18,
  "phoneNumbers": [
    { "Mobile": "111-111-1111" },
    { "Home": "222-222-2222" }
  ]
}

В этом примере видно, как поля разделяются запятыми, ключ от значения отделяется двоеточием, а значения могут быть разных типов: строки, числа, объекты и массивы[](https://docs.oracle.com/javaee/7/tutorial/jsonp001.htm).

### Особенности

1. **Человекочитаемый и лёгкий формат**. Код JSON интуитивно понятен для человека, что упрощает отладку и анализ. При этом он гораздо более «лёгкий», чем XML, поскольку не требует громоздких закрывающих тегов, что ускоряет передачу и обработку[](https://docs.oracle.com/javaee/7/tutorial/jsonp001.htm).
    
2. **Независимость от языка программирования**. Хотя JSON и произошёл от JavaScript, он является открытым стандартом и поддерживается подавляющим большинством современных языков программирования, включая Python, Java, C#, PHP, Go и другие.
    
3. **Иерархическая структура**. Благодаря возможности неограниченного вложения объектов и массивов, JSON позволяет строить древовидные структуры данных, идеально подходящие для представления сложных, взаимосвязанных сущностей[](https://docs.oracle.com/javaee/7/tutorial/jsonp001.htm).
    
4. **Отсутствие стандартной схемы**. JSON, в отличие от XML, не имеет широко распространённого стандарта для описания и проверки структуры данных (JSON Schema существует, но не является обязательной и не встроена в сам формат)[](https://docs.oracle.com/javaee/7/tutorial/jsonp001.htm).
    
5. **Роль в модели OSI**. JSON является протоколом уровня представления. Он берёт на себя задачу преобразования «родных» типов данных приложения в универсальный формат для передачи. Однако, JSON — «ограниченный» протокол, так как гарантирует представление лишь для небольшого набора базовых типов (строки, числа, булевы значения и т.д.). Из-за этого разработчики API часто вынуждены придумывать собственные способы представления бинарных данных, дат, времени и UUID поверх JSON, по сути, создавая свой собственный «слой представления»[](https://news.workers.tools/item?id=13934219).

### Как и где применяется

1. **Веб-API и микросервисы**. JSON является основным форматом для RESTful API. Практически все современные веб-сервисы (включая API социальных сетей, платёжных систем и облачных провайдеров) обмениваются данными именно в этом формате[](https://docs.oracle.com/javaee/7/tutorial/jsonp001.htm).
    
2. **Конфигурационные файлы**. JSON (и его диалекты, например, JSON5 или HOCON) широко используется для хранения настроек приложений, игр и инструментов разработки.
    
3. **NoSQL базы данных**. Документо-ориентированные базы данных, такие как MongoDB и CouchDB, используют JSON-подобные документы для хранения записей.
    
4. **Передача данных между клиентом и сервером**. В веб-приложениях JSON служит основным форматом для асинхронного обмена данными между браузером и сервером (AJAX-запросы), что позволяет обновлять страницу динамически, без её полной перезагрузки[](https://preprod.arquivo.pt/noFrame/patching/patching/record/20131106065644mp_/http://en.wikipedia.org/wiki/Json).
    
5. **Журналирование (логирование)**. Благодаря своей читаемости и простоте парсинга, JSON стал популярным форматом для структурированного логирования, позволяя легко анализировать и искать данные в логах.

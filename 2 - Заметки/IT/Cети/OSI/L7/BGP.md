**BGP (Border Gateway Protocol)** — это основной протокол динамической маршрутизации в Интернете. Он относится к классу протоколов маршрутизации внешнего шлюза (EGP) и предназначен для обмена информацией о достижимости сетей между автономными системами (AS). Протокол BGP принимает решения о маршрутизации на основе путей, правил сетевых политик или наборов правил, настроенных сетевым администратором. Благодаря своей масштабируемости, BGP является единственным протоколом, способным работать в сети размером с Интернет и эффективно управлять множеством соединений с независимыми доменами маршрутизации[](https://en.m.wikipedia.org/w/index.php?title=Border_Gateway_Protocol&curid=3966&printable=yes+).

### Особенности

1. Работа поверх TCP  
    В отличие от многих протоколов маршрутизации, BGP для обеспечения надёжности использует TCP (порт 179). После установки TCP-соединения между маршрутизаторами (BGP-спикерами) начинается обмен маршрутной информацией[](https://ru.wikipedia.org/wiki/Border_Gateway_Protocol).
    
2. Типы BGP: iBGP и eBGP  
    Протокол BGP существует в двух вариантах:
    
    - **External BGP (eBGP)**: Используется для обмена маршрутной информацией между разными автономными системами. Это основной механизм, связывающий Интернет воедино.
        
    - **Internal BGP (iBGP)**: Используется для распространения маршрутной информации внутри одной автономной системы. Он гарантирует, что все маршрутизаторы внутри AS имеют единое представление о внешних маршрутах.
        
3. Path Vector и атрибуты пути  
    BGP относится к классу протоколов типа "path vector". Он не просто сообщает о достижимости сети, но и передаёт список AS, через которые нужно пройти, чтобы до неё добраться (атрибут AS_PATH)[](https://ru.wikipedia.org/wiki/Border_Gateway_Protocol). Это позволяет избежать петель маршрутизации и принимать решения на основе полного пути. Ключевые атрибуты пути, влияющие на выбор маршрута:
    
    - **AS_PATH**: Список номеров AS, которые необходимо пройти.
        
    - **NEXT_HOP**: IP-адрес следующего маршрутизатора для достижения пункта назначения.
        
    - **LOCAL_PREF**: Атрибут, используемый внутри AS для выбора исходящего маршрута.
        
    - **MED (Multi_Exit_Disc)**: Используется для указания предпочтительного пути входа в AS при наличии нескольких соединений.
        
4. Механизм предотвращения петель  
    Основной механизм предотвращения петель в BGP — это проверка атрибута AS_PATH. Если маршрутизатор получает обновление маршрута, в AS_PATH которого уже содержится его собственный номер AS, это обновление игнорируется, что предотвращает зацикливание трафика.
    
5. Типы сообщений BGP  
    Для установки соединения и обмена информацией BGP использует несколько типов сообщений[](https://ru.wikipedia.org/wiki/Border_Gateway_Protocol):
    
    - **OPEN**: Отправляется для установки BGP-соединения после успешного создания TCP-сессии.
        
    - **UPDATE**: Используется для объявления о достижимости новых маршрутов или отзыва ранее объявленных.
        
    - **KEEPALIVE**: Периодически отправляется для подтверждения того, что соединение между BGP-соседями живо и активно.
        
    - **NOTIFICATION**: Отправляется в случае возникновения ошибки и приводит к закрытию BGP-соединения.
        
    - **ROUTE-REFRESH**: Используется для запроса повторной отправки маршрутной информации от соседа без разрыва соединения.
        
6. Уязвимости безопасности  
    BGP был разработан в эпоху, когда безопасность не была первостепенной задачей, и по умолчанию не имеет встроенных механизмов защиты[](https://www.haproxy.com/glossary/what-is-the-border-gateway-protocol-bgp). Он работает на принципе "доверия" к объявлениям соседей, что делает его уязвимым для:
    
    - **Перехвата (BGP Hijacking)**: Злоумышленник может объявить о принадлежности ему IP-адресов, которые на самом деле ему не принадлежат, перенаправляя трафик на свои серверы.
        
    - **Утечки (Route Leak)**: Ошибочная или злонамеренная передача маршрутной информации за пределы согласованных политик.  
        Для повышения безопасности разработаны расширения, такие как **RPKI (Resource Public Key Infrastructure)** и **BGPsec**, которые позволяют проверять происхождение маршрутов и их путь, но их внедрение происходит постепенно.

### Как и где применяется

1. Связывание автономных систем в глобальный Интернет  
    Это основное применение BGP. Когда ваше устройство обращается к веб-сайту на сервере в другой стране, именно BGP находит путь для передачи данных через множество независимых сетей провайдеров[](https://skillbox.ru/media/code/protokol-bgp-chto-eto-za-tehnologiya-i-kak-ona-obedinyaet-globalnye-seti/).
    
2. Обеспечение отказоустойчивости для дата-центров и компаний  
    Если организация получает услуги доступа в Интернет от двух разных провайдеров, BGP позволяет настроить политики для балансировки нагрузки и автоматического переключения на резервный канал в случае сбоя основного[](https://skillbox.ru/media/code/protokol-bgp-chto-eto-za-tehnologiya-i-kak-ona-obedinyaet-globalnye-seti/).
    
3. Управление трафиком и реализация политик  
    Интернет-провайдеры и крупные корпорации используют BGP для реализации сложных политик маршрутизации. С помощью атрибутов, таких как Local Preference и MED, они могут контролировать, какой путь будет считаться наилучшим для определённых типов трафика, например, отправляя голосовой трафик по более качественному каналу.

**DHCP (Dynamic Host Configuration Protocol)** — это сетевой протокол прикладного уровня, предназначенный для автоматической настройки сетевых параметров устройств при их подключении к IP-сети. Он решает ключевую задачу: избавляет администратора от необходимости вручную прописывать IP-адрес, маску подсети, шлюз по умолчанию и адреса DNS-серверов на каждом компьютере, принтере или смартфоне. Протокол работает по модели клиент-сервер и использует транспортный протокол UDP[](https://selectel.ru/blog/dhcp-protocol/)[](https://selectel.ru/blog/dhcp-protocol/).

---

### Принцип работы

Классический процесс получения сетевых настроек клиентом от сервера описывается мнемонической схемой **DORA**, которая объединяет четыре этапа обмена сообщениями[](https://selectel.ru/blog/dhcp-protocol/):

1. **Discovery (поиск)**. Подключившись к сети, клиент, не имеющий IP-адреса, отправляет широковещательное сообщение `DHCPDISCOVER` на адрес `255.255.255.255`, чтобы обнаружить доступные DHCP-серверы[](https://selectel.ru/blog/dhcp-protocol/)[](https://www.smart-soft.ru/blog/printsipy_raboty_protokola_dhcp/).
    
2. **Offer (предложение)**. Каждый DHCP-сервер, получивший запрос, отвечает клиенту сообщением `DHCPOFFER`, в котором предлагает свободный IP-адрес из своего пула, а также маску подсети и другие базовые параметры[](https://selectel.ru/blog/dhcp-protocol/)[](https://www.smart-soft.ru/blog/printsipy_raboty_protokola_dhcp/).
    
3. **Request (запрос)**. Клиент выбирает одно из предложений (обычно первое по времени) и отправляет серверу широковещательное сообщение `DHCPREQUEST`, подтверждая согласие получить указанные параметры[](https://selectel.ru/blog/dhcp-protocol/)[](https://www.smart-soft.ru/blog/printsipy_raboty_protokola_dhcp/).
    
4. **Acknowledge (подтверждение)**. Сервер фиксирует назначенный адрес за клиентом и отправляет подтверждающее сообщение `DHCPACK`. После его получения клиент применяет все сетевые настройки[](https://selectel.ru/blog/dhcp-protocol/)[](https://www.smart-soft.ru/blog/printsipy_raboty_protokola_dhcp/).
    

**Другие режимы взаимодействия**  
Помимо четырёхэтапного процесса, существуют другие способы взаимодействия клиента и сервера. Клиент может запросить ранее использовавшийся IP-адрес, отправив серверу сообщение `DHCPREQUEST`. В ответ он получит либо подтверждение `DHCPACK`, либо отказ `DHCPNAK`, если адрес уже занят. Продление срока аренды адреса также выполняется с помощью сообщения `DHCPREQUEST`. Если клиенту необходимо освободить IP-адрес досрочно (например, перед выключением), он отправляет серверу сообщение `DHCPRELEASE`.

### Особенности

**Аренда IP-адресов (Lease).** Протокол не выдаёт IP-адрес навсегда, а предоставляет его в аренду на определённый срок. Это позволяет возвращать неиспользуемые адреса в общий пул и эффективно распределять их между устройствами, особенно в мобильных сетях. За некоторое время до истечения срока аренды клиент автоматически пытается продлить её, отправив серверу запрос `DHCPREQUEST`.

**Опции (Options).** Механизм, который позволяет серверу передавать клиенту не только IP-адрес, но и другие важные параметры: маску подсети (Option 1), адрес шлюза по умолчанию (Option 3), адреса DNS-серверов (Option 6) и т.д. Это делает процесс конфигурации полностью автоматизированным.

**Агент ретрансляции (Relay Agent).** Поскольку запросы `DHCPDISCOVER` являются широковещательными, они по умолчанию не проходят через маршрутизаторы. Агент ретрансляции, настроенный на маршрутизаторе, перехватывает такие запросы и пересылает их напрямую (unicast) на DHCP-сервер, который может находиться в другой подсети, а затем возвращает ответ клиенту. Это позволяет использовать один центральный сервер для обслуживания нескольких сегментов сети[](https://help.ptsecurity.com/ru-RU/projects/ngfw/latest/help/9469852171).

**Типы адресации.** Протокол поддерживает три режима:

- **Динамическая адресация:** сервер выдает адрес из пула на ограниченный срок.
    
- **Автоматическая адресация:** сервер выдает постоянный адрес (фактически бесконечная аренда).
    
- **Статическая адресация:** администратор вручную прописывает соответствие между MAC-адресом устройства и выдаваемым ему IP-адресом (по сути, резервирование адреса).
    

**Версии протокола.** Основная версия `DHCPv4` предназначена для сетей IPv4. Для IPv6 была разработана версия `DHCPv6`, которая имеет ряд отличий: в IPv6 часто используется SLAAC (автоконфигурация без сохранения состояния), а `DHCPv6` применяется для выдачи дополнительных параметров (например, DNS) или, в режиме с сохранением состояния, для централизованного управления адресами.

### Кто и что делает

Существует:

- **DHCP-сервер** (предоставляет настройки),
    
- **DHCP-клиент** (запрашивает настройки).
    

### Как работает сценарий аренды

Клиент делает запрос, сервер отвечает предложением, после чего клиент запрашивает/использует аренду.

Ключевые параметры:

- **DHCP lease time** (время аренды), которое задаётся администратором; лектор упоминает, что по умолчанию встречаются значения порядка **10 минут** и т.п., но точное значение зависит от конфигурации.

### Безопасность

Упомянута демонстрация атаки на DHCP-сервер в бонусных материалах; после этого настройки выдачи могли «сломаться», что иллюстрирует риск компрометации сервиса.

### Как и где применяется

**Домашние и офисные сети.** Это самое массовое применение. Домашний роутер выступает в роли DHCP-сервера, раздавая адреса всем подключённым устройствам (компьютерам, телефонам, телевизорам). Это позволяет подключать новые устройства без каких-либо ручных настроек.

**Корпоративные и провайдерские сети.** В крупных сетях протокол используется для централизованного управления адресным пространством, автоматизации выдачи конфигураций и контроля за использованием адресов.

**Гостевые сети Wi-Fi.** В точках доступа и гостевых порталах протокол изолирует гостевой трафик в отдельную подсеть, выдавая временные IP-адреса и обеспечивая базовую безопасность.

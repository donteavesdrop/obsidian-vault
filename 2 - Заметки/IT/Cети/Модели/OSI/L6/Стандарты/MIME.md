**MIME (Multipurpose Internet Mail Extensions)** — это не протокол в классическом понимании, а интернет-стандарт (RFC 2045–2049), который расширил возможности исходного почтового протокола для передачи не-ASCII данных. Стандарт определяет набор дополнительных заголовков, позволяющих передавать в одном письме текст на разных языках, файлы различных форматов и структурированные данные. Успех MIME оказался настолько велик, что его архитектура была позже адаптирована для HTTP, сделав возможной загрузку любых файлов в интернете.

---

### Принцип работы

Исходный протокол электронной почты был предназначен только для передачи 7-битного ASCII-текста. MIME не заменяет SMTP, а расширяет его: он преобразует исходные данные (например, изображение или файл на кириллице) в формат, который гарантированно пройдёт через сетевые шлюзы и будет правильно интерпретирован на стороне получателя. Этот процесс включает два этапа:

1. **Маркировка**: В заголовки письма добавляются специальные поля (MIME-Version, Content-Type, Content-Transfer-Encoding), которые сообщают почтовому клиенту о типе содержимого и способе его кодирования.
    
2. **Преобразование (кодирование)**: Для отправки бинарного файла (например, изображения) данные перекодируются в 7-битный ASCII-текст с помощью одного из методов кодирования (base64, quoted-printable). На принимающей стороне происходит обратное декодирование, и файл восстанавливается в исходном виде.

### Особенности

**История создания.** До появления MIME для отправки файлов требовались ручные манипуляции: пользователи кодировали файлы утилитами uuencode или BinHex и вставляли полученный текст в тело письма. Стандарт MIME, разработанный Натаниэлем Боренштейном и Недом Фридом, автоматизировал этот процесс. Первое в мире MIME-вложение (изображение и песня мужского квартета) было отправлено 11 марта 1992 года.

**Пять новых заголовков.** Для поддержки нетекстового содержимого MIME вводит ключевые заголовки:

- **MIME-Version**: Всегда `1.0`, указывает на соответствие сообщения стандарту.
    
- **Content-Type**: Определяет тип содержимого (например, `text/html`, `image/jpeg`). Для составных сообщений также задаёт разделитель (boundary).
    
- **Content-Transfer-Encoding**: Указывает метод преобразования бинарных данных в текстовые (например, `base64`).
    
- **Content-Disposition**: Советует почтовому клиенту, нужно ли показывать содержимое в теле письма или предлагать его сохранить как файл (`attachment`).
    
- **Content-ID**: Уникальный идентификатор, позволяющий ссылаться на встроенные ресурсы из HTML-кода.
    

**MIME-типы (медиа-типы).** Глобальная система идентификации форматов, управляемая IANA. Каждый тип имеет иерархическую структуру `тип/подтип` (например, `image/png` или `video/mp4`), что позволяет приложениям понять, как обрабатывать полученные данные, не полагаясь на расширения файлов.

**Кодирование содержимого.** Основные методы:

- **Quoted-Printable**: Кодирует 8-битные символы в `=` и шестнадцатеричный код, эффективен для текста с редкими не-ASCII символами (например, языков с диакритикой).
    
- **Base64**: Наиболее распространённый метод для бинарных файлов, кодирующий каждые 3 байта в 4 печатных ASCII-символа.
    
- **7bit / 8bit / Binary**: Базовые методы, оставленные для совместимости.
    

**Многочастные сообщения (Multipart).** Позволяют объединять разные части в одном письме:

- `multipart/mixed`: Стандартный тип для письма с вложениями.
    
- `multipart/alternative`: Предлагает несколько версий одного содержимого (например, `text/plain` и `text/html`).
    
- `multipart/related`: Для HTML-писем, где изображения встроены в тело и на них ссылаются через Content-ID.
    

**Роль в модели OSI.** MIME работает на **уровне представления (Layer 6)**, так как его задача — преобразование данных (кодирование, сериализация) для обеспечения совместимости между разными системами.

### Как и где применяется

1. **Электронная почта.** Изначальная и основная область применения. MIME позволяет современным почтовым системам (Gmail, Outlook) обрабатывать письма с вложениями, форматированным текстом, эмодзи и файлами любых типов.
    
2. **Веб (HTTP).** MIME-типы (в HTTP называемые `Content-Type`) используются браузерами для определения типа ресурса: является ли ответ сервера HTML-страницей (`text/html`), CSS-файлом (`text/css`), JSON-данными (`application/json`) или изображением (`image/jpeg`).
    
3. **Веб-формы (`multipart/form-data`).** Специальный тип `multipart/form-data` используется HTML-формами для загрузки файлов на сервер. Без него передача бинарных данных (фотографий, документов) через веб-формы была бы невозможна.
    
4. **Сетевые протоколы.** MIME-типы используются в протоколах сигнализации для описания медиа-сессий (какой аудио/видеокодек будет использоваться) и в других системах для единообразного обозначения типов данных.

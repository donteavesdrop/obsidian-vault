# FTP (File Transfer Protocol)

## Общее описание

**FTP (File Transfer Protocol)** — это стандартный сетевой протокол прикладного уровня, предназначенный для передачи файлов между клиентом и сервером в сетях TCP/IP. Он обеспечивает аутентификацию пользователя, навигацию по файловой системе сервера, а также загрузку и выгрузку файлов. Протокол был разработан в 1971 году (задолго до появления современного интернета) и остаётся одним из самых простых и распространённых способов обмена файлами. Официальное описание протокола можно найти в **RFC 959**.

---

## Принцип работы

Ключевая особенность FTP — использование **двух отдельных TCP-соединений** между клиентом и сервером: управляющего и канального (data).

1. **Управляющее соединение (Control Connection).** Клиент устанавливает TCP-соединение с сервером на 21-й порт. Это соединение остаётся открытым на протяжении всей сессии и используется для передачи команд (`USER`, `PASS`, `LIST`, `RETR`, `STOR`) и кодов ответа сервера. Управляющее соединение передаёт команды в текстовом виде (одна команда — одна строка).

2. **Канальное соединение (Data Connection).** Каждый раз, когда необходимо передать список файлов, загрузить или скачать файл, клиент и сервер открывают новое TCP-соединение для передачи данных. Это соединение закрывается сразу после завершения передачи файла или списка.

Для работы необходимо наличие **FTP-сервера**, который обрабатывает входящие запросы. Основные этапы работы:

- Установка управляющего соединения. Клиент подключается к серверу и проходит аутентификацию (логин, пароль, либо анонимный доступ).
- Передача команд. Клиент отправляет запросы, например, на просмотр списка файлов или загрузку данных.

## Особенности

### Два режима передачи данных: активный и пассивный

Проблема работы FTP через межсетевые экраны (фаерволы) и NAT привела к созданию двух режимов.

- **Активный режим (Active Mode).** Клиент сообщает серверу свой IP-адрес и порт (командой `PORT`). Сервер сам инициирует соединение с этого порта клиента для передачи данных. Проблема: клиент часто находится за NAT или фаерволом, который блокирует входящие соединения от сервера.
- **Пассивный режим (Passive Mode).** Клиент отправляет команду `PASV`. Сервер открывает порт для данных (в диапазоне выше 1024) и сообщает его клиенту. Теперь клиент сам инициирует соединение с этого порта сервера. Этот режим решает проблемы с NAT и фаерволами и является предпочтительным для современных сетей.

###  Режимы передачи файлов

FTP может передавать файлы в двух режимах:

- **ASCII-режим:** используется для текстовых файлов. Клиент и сервер могут преобразовывать окончания строк (CRLF, LF) в соответствии с требованиями своей ОС.
- **Бинарный режим (Binary/Image):** используется для изображений, архивов, исполняемых файлов. Данные передаются «как есть», без преобразований.

### Аутентификация и анонимный доступ

FTP поддерживает аутентификацию по логину и паролю, передаваемым в открытом виде (управляющее соединение не шифруется). Также существует **анонимный FTP (Anonymous FTP)**, где в качестве логина используется `anonymous`, а паролем обычно служит email адрес пользователя. Анонимный FTP широко использовался для публичного распространения программного обеспечения и файлов.

### Отсутствие шифрования (уязвимость)

Основной недостаток FTP: все данные (логин, пароль, передаваемые файлы) передаются в незашифрованном виде. Это делает протокол уязвимым для атак перехвата трафика (sniffing). Для защищённой передачи существуют расширения: **FTPS** (FTP over SSL/TLS) и **SFTP** (SSH File Transfer Protocol), которые не совместимы с классическим FTP.

###  Команды и коды ответов

FTP использует текстовые команды (например, `USER`, `PASS`, `CWD`, `LIST`, `RETR`, `STOR`) и трёхзначные коды ответов (например, `220` — готов к работе, `331` — требуется пароль, `226` — передача данных завершена, `550` — файл недоступен).

## Достоинства и недостатки FTP

### Преимущества

- **Простота использования.** FTP легко настраивается и не требует сложных конфигураций. Для работы со стороны клиента достаточно ввести IP-адрес сервера, логин и пароль.
- **Поддержка больших файлов.** FTP позволяет передавать файлы любого размера. Также присутствует возможность возобновления загрузки после обрыва соединения.
- **Гибкость при работе с файлами и директориями.** FTP позволяет создавать, удалять, переименовывать файлы и директории прямо на сервере в процессе установления сессии, если у пользователя есть соответствующие права.
- **Поддержка безопасных расширений (FTPS, SFTP).** Хотя классическая версия протокола не является безопасной, существуют расширения, которые обеспечивают шифрование данных.

### Недостатки

- **Проблемы безопасности.** Классическая версия протокола не шифрует данные. FTP также восприимчив к атакам типа Brute-force, MITM, DDoS. Для решения первой проблемы можно использовать FTPS или SFTP, а для второй — дополнительную защиту при помощи брандмауэров, программ наподобие fail2ban, а также встроенных функций FTP-сервера.
- **Отсутствие встроенной проверки целостности файлов.** В классической версии протокола FTP не предусмотрен встроенный механизм для проверки файла на целостность. Это означает, что при передаче данных через FTP нет гарантии, что файл не был поврежден или изменён в процессе передачи.
- **Ограниченная поддержка современных технологий.** FTP не поддерживает сжатие данных во время передачи, что может замедлить процесс загрузки и выгрузки файлов. Кроме того, в протоколе отсутствует встроенный функционал для работы с символическими ссылками.

## Как и где применяется

### Загрузка и обновление веб-сайтов

Исторически FTP был основным способом для веб-разработчиков загружать файлы сайтов на хостинг. Хотя сегодня его всё чаще заменяют более безопасные протоколы (SFTP, SCP) и системы контроля версий, многие хостинг-провайдеры до сих пор поддерживают FTP.

### Обмен большими файлами

Внутри корпоративных сетей FTP используется для передачи больших объёмов данных между серверами, для автоматического резервного копирования и синхронизации файлов.

### Доступ к публичным файловым архивам

До сих пор существуют публичные FTP-серверы университетов, научных организаций и архивов программного обеспечения, предоставляющие анонимный доступ к коллекциям файлов (например, зеркала дистрибутивов Linux).

### Автоматизация передачи данных

Протокол поддерживается многими скриптовыми языками и утилитами командной строки (например, `ftp`, `lftp`, `curl`), что позволяет автоматизировать процессы передачи файлов в пакетных сценариях. Обычно FTP используется в сочетании с программами-клиентами, такими как **FileZilla** или **WinSCP**, которые упрощают работу с протоколом.

### Типичные сценарии использования FTP

- Передача файлов — загрузка или скачивание больших файлов (изображений, видеозаписей, программ и прочего).
- Управление файлами на сервере — удалённое перемещение, переименование, удаление и т. д.

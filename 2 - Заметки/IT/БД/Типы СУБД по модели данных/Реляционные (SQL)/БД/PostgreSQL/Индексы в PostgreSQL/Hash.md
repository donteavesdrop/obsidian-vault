## Индексирование: Hash-индексы

### Принцип работы хеш-индекса

![[Pasted image 20260427165733.png]]
```sql
SELECT lname FROM testhash WHERE fname = 'Peter';
```

---

### Структура хеш-индекса

| Тип страницы | Описание |
|--------------|----------|
| **Метастраница (meta page)** | нулевая страница, содержит информацию о том, что находится внутри индекса |
| **Страницы корзин (bucket page)** | основные страницы индекса, хранят данные в виде пар «хеш-код — TID» |
| **Страницы переполнения (overflow page)** | устроены так же, как страницы корзин, используются, когда одной страницы для корзины не хватает |
| **Страницы битовой карты (bitmap page)** | отмечаются освободившиеся страницы переполнения, которые можно использовать для других корзин |

### Особенности хеш-индексов

| Особенность | Описание                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| ⚠️          | Нельзя использовать данные в индексе, чтобы избежать чтения строк                                         |
| ⚠️          | Нельзя использовать для сортировки, поскольку строки в нём не хранятся в отсортированном порядке          |
| ⚠️          | Не поддерживают поиск по частичному ключу, так как хеш-коды вычисляются для всего индексируемого значения |
| ✅           | Поддерживают только сравнения на равенство, использующие операторы `=`, `IN()` и `<=>`                    |
| ✅           | Доступ к данным в хеш-индексе очень быстр, если нет большого количества коллизий                          |
| ⚠️          | Некоторые операции обслуживания индекса могут оказаться медленными, если количество коллизий велико       |

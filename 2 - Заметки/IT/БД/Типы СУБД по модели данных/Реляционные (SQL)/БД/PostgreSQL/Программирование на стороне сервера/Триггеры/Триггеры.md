## Триггер

**Триггер** – это откомпилированная SQL-процедура, исполнение которой обусловлено наступлением определенных событий внутри реляционной базы данных.

Триггеры – особый инструмент SQL-сервера, используемый для **поддержания целостности данных** в базе данных.

Триггер представляет собой специальный тип хранимых процедур, запускаемых сервером **автоматически** при попытке изменения данных в таблицах, с которыми триггеры связаны.

---

### События, активирующие триггер

| Событие | Описание |
|---------|----------|
| ✨ **INSERT** | Ввод новой строки |
| ✏️ **UPDATE** | Изменение значений одного или нескольких столбцов таблицы |
| 🗑️ **DELETE** | Удаление строк таблицы |

---

## Синтаксис создания триггера

```sql
CREATE TRIGGER имя_триггера
BEFORE | AFTER | INSTEAD OF <триггерное_событие>
ON <имя_таблицы>
[REFERENCING <список_старых_или_новых_псевдонимов>]
[FOR EACH { ROW | STATEMENT }]
[WHEN (условие_триггера)]
<тело_триггера>
```

---

## Ограничения триггеров

| Ограничение | Описание |
|-------------|----------|
| ❌ | Нельзя использовать в теле триггера операции **создания** объектов базы данных (новую базу, таблицу, индекс, процедуру, триггер, представление) |
| ❌ | Нельзя использовать в триггере команду **удаления** объектов `DROP` |
| ❌ | Нельзя использовать в теле триггера команды **изменения** базовых объектов `ALTER` |
| ❌ | Нельзя изменять **права доступа** к объектам базы данных |
| ❌ | Триггер **не может возвращать** никаких значений |

---

## Зачем нужны триггеры

| Цель | Описание |
|------|----------|
| 🔒 | Реализация **сложных ограничений целостности** данных, которые невозможно реализовать через ограничения, устанавливаемые при создании таблицы |
| 📝 | **Контроль информации**, хранимой в таблице, посредством регистрации вносимых изменений и пользователей, производящих эти изменения |
| 🔔 | **Автоматическое оповещение** других программ о том, что необходимо делать в случае изменения информации, содержащейся в таблице |
| 📢 | **Публикация информации** о различных событиях |

---

## Типы триггеров

| Тип | Описание |
|-----|----------|
| **DML-триггеры** | Активизируются предложениями ввода, обновления и удаления информации (`INSERT`, `UPDATE`, `DELETE`) до или после выполнения предложения, на уровне строки или таблицы |
| **INSTEAD OF (триггеры замещения)** | Создаются только для **представлений**. Выполняются **вместо** предложений DML, вызывающих их срабатывание |
| **Системные триггеры** | Активизируются не на предложение DML, а на **системное событие** (например, запуск или остановка БД). Также срабатывают на предложения DDL (например, `CREATE TABLE`) |

## Принцип работы триггера

```
┌─────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  DML-запрос │ ──► │  Срабатывание   │ ──► │  Выполнение     │
│ (INSERT/    │     │  триггера       │     │  тела триггера  │
│  UPDATE/    │     │                 │     │                 │
│  DELETE)    │     └─────────────────┘     └─────────────────┘
└─────────────┘                                      │
                                                     ▼
┌─────────────────────────────────────────────────────────┐
│  Результат:                                             │
│  • Изменение данных                                     │
│  • Откат операции                                       │
│  • Дополнительные действия (логирование, проверки и т.д.)│
└─────────────────────────────────────────────────────────┘
```

## Пример триггера

**Задача:** Триггер, который срабатывает при удалении экземпляра некоторой рабочей книги (например, в случае утери этой книги сотрудником). Триггер проверяет:
- если остался ещё хоть один экземпляр данной книги — ничего не делает;
- если это был последний экземпляр книги в библиотеке — удаляет описание данной книги из каталога.

```sql
CREATE TRIGGER del_exemp ON books_ex
FOR DELETE
AS
DECLARE @Ntek int 
DECLARE @del_ex varchar(12)
BEGIN
    SELECT @del_ex = ISBN FROM deleted
    EXEC @Ntek = COUNT_EX @DEL_EX 
    IF @Ntek = 0
        DELETE FROM BOOKS
        WHERE BOOKS.ISBN = @DEL_EX
END
```

### MVCC (Multiversion Concurrency Control)

Реализация транзакций в СУБД PostgreSQL основана на **многоверсионной модели (MVCC)**.

### Принцип работы MVCC

| Аспект | Описание |
|--------|----------|
| **Снимок данных (snapshot)** | Каждый SQL-оператор видит согласованную версию базы данных, которую она имела на определённый момент времени |
| **Изоляция** | Параллельно исполняемые транзакции, даже вносящие изменения в базу данных, не нарушают согласованности данных этого снимка |
| **Защита от несогласованности** | Каждый SQL-оператор видит снимок данных (версию базы данных) на определённый момент времени, вне зависимости от текущего состояния данных. Это защищает операторы от несогласованности данных, возможной, если другие конкурирующие транзакции внесут изменения в те же строки данных, и обеспечивает тем самым изоляцию транзакций для каждого сеанса баз данных |

### Преимущества MVCC

| Преимущество | Описание |
|--------------|----------|
| **Снижение конфликтов блокировок** | MVCC отходит от методик блокирования, принятых в традиционных СУБД, снижает уровень конфликтов блокировок и обеспечивает более высокую производительность в многопользовательской среде |
| **Чтение не мешает записи** | Блокировки MVCC, полученные для чтения данных, **не конфликтуют** с блокировками, полученными для записи. Чтение никогда не мешает записи, а запись — чтению |
| **Дополнительные средства блокировки** | Для приложений, которым в принципе не нужна полная изоляция транзакций и которые предпочитают явно определять точки конфликтов, в PostgreSQL также есть средства блокировки на уровне таблиц и строк |

> При правильном использовании MVCC обычно обеспечивает **лучшую производительность**.

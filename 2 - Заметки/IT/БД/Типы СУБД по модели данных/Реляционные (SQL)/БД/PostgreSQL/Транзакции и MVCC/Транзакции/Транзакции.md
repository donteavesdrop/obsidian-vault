## Транзакции

**Транзакцией** называется множество операций, выполняемое приложением, которое переводит базу данных из одного корректного состояния в другое корректное состояние при условии, что транзакция выполнена полностью и без помех со стороны других транзакций.

### Исходы транзакции

| Исход | Описание |
|-------|----------|
| **Фиксация (COMMIT)** | изменения данных, произведенные в ходе выполнения, успешно зафиксированы в базе данных |
| **Откат (ROLLBACK)** | транзакция отменяется, и отменяются все изменения, выполненные в её рамках |

> Транзакция переводит базу данных из одного **согласованного состояния** в другое согласованное состояние.

**Отмена транзакции называется откатом (ROLLBACK).**

Современные СУБД предлагают специальные механизмы для организации **параллельного**, т.е. одновременного, выполнения транзакций.

## Свойства транзакций согласно теории баз данных (ACID)

| Свойство | Описание |
|----------|----------|
| **Атомарность (Atomicity)** | Либо транзакция будет зафиксирована в базе данных полностью (результаты выполнения всех её операций), либо не будет зафиксирована ни одна операция транзакции |
| **Согласованность (Consistency)** | В результате успешного выполнения транзакции база данных переводится из одного согласованного состояния в другое согласованное состояние |
| **Изолированность (Isolation)** | Во время выполнения транзакции другие транзакции должны оказывать по возможности минимальное влияние на неё |
| **Долговечность (Durability)** | После успешной фиксации транзакции пользователь должен быть уверен, что данные надежно сохранены в базе данных и впоследствии могут быть извлечены из неё, независимо от последующих возможных сбоев в работе системы |

## Особенности транзакций в PostgreSQL

### Режим AUTOCOMMIT

PostgreSQL каждый SQL-оператор обрабатывает как транзакцию. Фактически работает в режиме **AUTOCOMMIT**.

### Объединение операторов в транзакцию

Если нужно несколько операторов объединить в одну транзакцию, их заключают в команды `BEGIN` и `COMMIT` (или `ROLLBACK`):

```sql
BEGIN;
-- операторы SQL
COMMIT;  -- или ROLLBACK;
```

### Точки сохранения (SAVEPOINT)

Операторами в транзакции можно также управлять на более детальном уровне, используя **точки сохранения**. Точки сохранения позволяют выборочно отменять некоторые части транзакции и фиксировать все остальные.

```sql
SAVEPOINT имя_точки;
-- операции
ROLLBACK TO имя_точки;  -- откат к точке сохранения
```

> Определив точку сохранения с помощью `SAVEPOINT`, при необходимости можно вернуться к ней с помощью команды `ROLLBACK TO`. Все изменения в базе данных, произошедшие после точки сохранения и до момента отката, **отменяются**, но изменения, произведённые ранее, **сохраняются**.

### Управление точками сохранения

| Команда | Описание |
|---------|----------|
| `RELEASE [SAVEPOINT] имя_точки` | высвободить ранее определённую точку сохранения |

> **Важно:** Когда происходит возврат к точке сохранения, она продолжает существовать, так что к ней можно откатываться несколько раз. Если это не нужно, такую точку сохранения необходимо удалить, чтобы система высвободила ресурсы.
>
> При удалении или откате к точке сохранения **все точки сохранения, определённые после неё, автоматически уничтожаются**.

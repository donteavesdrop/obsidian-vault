## Уровень изоляции REPEATABLE READ в PostgreSQL

### Основные принципы

**Repeatable Read** — это уровень изоляции, при котором транзакция видит только те данные, которые были зафиксированы до её начала. Незафиксированные изменения других транзакций не видны. Изменения, внесённые параллельными транзакциями после начала текущей, также остаются невидимыми.

**Ключевое отличие от Read Committed** заключается в том, что снимок данных создаётся не перед каждым оператором, а **один раз — перед первым оператором транзакции**. Поэтому все SELECT-запросы внутри транзакции видят одни и те же данные.

### Важное предупреждение

Приложения, использующие этот уровень изоляции, должны быть готовы **повторять транзакции** в случае сбоев сериализации.

### Поведение при изменении данных

Команды UPDATE, DELETE, SELECT FOR UPDATE и SELECT FOR SHARE ищут целевые строки среди тех, что существовали на момент начала транзакции. Если другая параллельная транзакция уже изменила или заблокировала нужную строку, возможны два сценария:

1.  **Первая транзакция откатится** — текущая транзакция продолжит работу с исходной строкой.
2.  **Первая транзакция успешно зафиксируется и изменит строку** — текущая транзакция будет отменена с ошибкой: *«ОШИБКА: не удалось сериализовать доступ из-за параллельного изменения»*.

### Пошаговый пример

Рассмотрим пример с таблицей `aircrafts_tmp`.

**Исходные данные (видны обеим транзакциям до начала работы):**

*   320 | Airbus A320-200 | 5700
*   321 | Airbus A321-200 | 5600
*   319 | Airbus A319-100 | 6700
*   SU9 | Sukhoi SuperJet-100 | 3700
*   CN1 | Cessna 208 Caravan | 2100
*   CR2 | Bombardier CRJ-200 | 1900

---

**Транзакция 1 (начинается первой):**

```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ;

-- Запрос видит исходные данные
SELECT * FROM aircrafts_tmp;
```

**Транзакция 2 (начинается параллельно):**

```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ;

-- Транзакция 2 тоже видит исходные данные
SELECT * FROM aircrafts_tmp;

-- Добавляем новый самолёт IL9
INSERT INTO aircrafts_tmp VALUES ('IL9', 'Ilyushin IL96', 9800);
-- Увеличиваем дальность у Airbus A320
UPDATE aircrafts_tmp SET range = range + 100 WHERE aircraft_code = '320';

-- Фиксируем изменения во второй транзакции
COMMIT;
```

После фиксации второй транзакции данные в таблице изменились.

**Транзакция 1 (продолжает работать со своим старым снимком):**

```sql
-- Всё ещё видит данные с момента начала транзакции 1
-- Новый самолёт IL9 НЕ ВИДЕН
-- Старое значение дальности A320 (5700) ВИДНО
SELECT * FROM aircrafts_tmp;
```

**Транзакция 1 (пытается изменить данные, которые уже были изменены транзакцией 2):**

```sql
-- Попытка обновить ту же строку (Airbus A320)
UPDATE aircrafts_tmp SET range = range + 100 WHERE aircraft_code = '320';
```

**Результат:**
Транзакция 1 завершится с ошибкой, так как строка уже была изменена параллельной транзакцией, которая успешно зафиксировалась.

*ОШИБКА: не удалось сериализовать доступ из-за параллельного изменения*

### Резюме

*   **Грязное чтение:** Не допускается.
*   **Неповторяющееся чтение:** Не допускается (все SELECT внутри транзакции видят один снимок).
*   **Фантомное чтение:** Возможно (другая транзакция может добавить новые строки, удовлетворяющие условию, но текущая транзакция их не увидит).
*   **Конфликт параллельных изменений:** Приводит к ошибке и требует повторного выполнения транзакции.
